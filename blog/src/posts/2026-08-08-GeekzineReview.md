### GeekNews, 자주 보다 보니 눈이 좀 피곤했다

평소 [GeekNews](https://news.hada.io)를 즐겨 읽는다. 정보 밀도 높은 HN 스타일 UI라 콘텐츠는 알찬데, 폰트는 작고 줄 간격은 촘촘해서 오래 읽으면 눈이 금방 피로해졌다. **"매거진 페이지처럼 편안하게 읽을 순 없을까?"** 하는 생각이 계속 맴돌았다.

크롬 익스텐션은 한 번도 만들어본 적이 없었다. Manifest V3 구조도 모르고, `content_script`가 어느 타이밍에 주입되는지, `chrome.storage`는 언제 어떻게 써야 하는지도 감이 없었다. 근데 이번엔 그냥 부딪혀보기로 했다.

### 해결: 클로드랑 붙어서 하나씩 뜯어봤다 🔍

목표는 명확했다. **폰트는 17px, 줄 간격은 1.75~1.85, 여백은 넉넉하게. 라이트/다크 테마도 지원.** 디자인 컨셉을 먼저 잡고, 클로드랑 같이 GeekNews의 원본 CSS를 하나씩 뜯어보는 방식으로 진행했다. 이때 많이 참고했던 게 마찬가지로 자주 읽는 [뉴닉](https://newneek.co/)이다.

가장 오래 붙잡고 있었던 건 `.topic_row`의 3컬럼 grid 레이아웃이었다. `grid-template-columns: 12px 24px 1fr`로 짜여 있고, 투표 버튼이 `grid-column-start: 3`으로 고정돼 있어서, 내가 원하는 블록형 레이아웃으로 바꾸려면 grid 구조 자체를 갈아엎어야 했다. 여기에 `.commentTD { overflow: hidden }` 때문에 댓글 들여쓰기 요소가 자꾸 잘려나가는 문제까지 겹쳐서, 이게 단순 CSS 문제인지 레이아웃을 통째로 바꿔야 하는 문제인지 한동안 헷갈렸다.

이럴 때마다 원본 CSS 구조를 클로드한테 던져주고 **이 규칙이 왜 이렇게 짜여 있는지, override하려면 정확히 뭘 건드려야 하는지**를 같이 물어보면서 작업했다. 혼자였다면 개발자 도구에서 CSS 하나씩 껐다 켰다 하면서 원인을 찾는 데만 몇 시간은 더 썼을 것 같다.

무엇보다 좋았던 건, **문제점을 찾으면 바로바로 해결할 수 있었다는 점**이다. "이 부분 줄바꿈이 이상해" 하면 원인부터 같이 찾고, 바로 고쳐서 적용해보고, 아니면 다시 고치고. 이 루프가 빨라지니까 만드는 재미가 계속 붙었다!

그렇게 만든 게 **[GeekZine](https://github.com/white-jang/GeekZine)** 이다. 메인 리스트, 토픽 상세, 댓글, GeekBots/GeekBadge/Weekly 페이지까지 스타일링을 붙였고, 팝업에서 라이트/다크 테마를 토글하면 `chrome.storage.sync`로 탭 간에 동기화되도록 만들었다.

### 성과: 최근 90일 기준, 설치 126건

Chrome 웹스토어에 올리고 나서 **최근 90일 기준 설치 126건**을 찍었다. 엄청난 숫자는 아니지만, 내가 실제로 불편해서 만든 걸 낯선 누군가가 설치해서 쓰고 있다는 게 신기하고 뿌듯했다! 😸

시간이 된다면 시스템 다크모드 자동 감지, 폰트 크기 조절 슬라이더 등의 기능을 더 붙일 예정이다. 내가 가장 많이 사용하는 사용자로서 겪는 불편함을 계속해서 업데이트하려고 한다.

### 회고

이번 프로젝트를 시작할 때만 해도 "그냥 눈 편하게 보려고 만드는 작은 사이드 프로젝트"라고 생각했다. 근데 끝나고 보니 남은 건 그것보다 많았다.

크롬 익스텐션이라는 새로운 영역에 처음 뛰어들면서, 남이 짜놓은 CSS 구조 위에서 원인을 진단하고 override 전략을 짜는 감각을 실전으로 익힐 수 있었다. 특히 grid 레이아웃 갈아엎기나 `color-scheme` 이슈처럼 혼자였으면 삽질만 하다 지쳤을 문제들을, 클로드랑 같이 원인부터 짚어가며 풀어낸 게 컸다. 막힐 때마다 "이거 왜 이래?"를 바로 물어보고 답을 얻는 루프가 빨라지니까, 새로운 걸 배우는 부담이 확실히 줄었다.

다음엔 시스템 테마 자동 감지나 폰트 크기 조절 같은 남은 TODO를 마저 채워보고 싶다. 그리고 이번에 익힌 **AI랑 같이 원인을 진단하고 문제를 좁혀가는 방식**을 다음 프로젝트에도 그대로 가져가보려 한다.
